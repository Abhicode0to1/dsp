- ✅ **Two-chats-at-once bug.** Fixed a bug where a customer could accidentally start two live chats simultaneously (e.g. by double-clicking "Start Chat"). The system now allows only one active chat per customer.
- ✅ **Stale "incoming chat" indicator after accepting.** Fixed a bug where the agent's notification bell kept showing "incoming chat" even after they'd already accepted it. The badge now clears properly the moment they accept.

- ✅ **Endless ring loop when only one agent is online.** Fixed a bug where the system would keep ringing the same agent every couple of seconds forever if they were the only one online and didn't accept. Now it rings once, then waits quietly until something changes (e.g. they finish another chat).
- ✅ **End-chat button taking nearly a minute.** Fixed a test problem where ending a chat sometimes took nearly 60 seconds because an unrelated popup was sitting on top of the Dismiss button. The end-chat flow now consistently finishes in under a second.
- ✅ **Dashboard freezing during a burst of notifications.** Fixed a bug where the customer dashboard would freeze for several seconds when many notifications arrived in a burst. The bell now handles bursts smoothly — 10 events in a row no longer lock up the page.
- ✅ **False "notifications lost" in load test results.** Fixed a measurement bug in the load tests that was making it look like 17% of notifications were being lost. Actual loss is zero — the test was firing notifications before the customer's browser had fully connected to the server.
- ✅ **Email noise reduction — 80% volume cut.** Cut roughly 80% of the emails our system sends. Three categories of duplicate emails (ticket-assignment-to-agent, customer-reply-to-agent, chat-accepted-to-customer) now rely on the in-app notification instead. ## 🔑 Key design choices made along the way

- **Logging in on a new device logs you out of old ones.** Stops stolen sessions from being reused indefinitely. Old tabs see a "session ended elsewhere" message and redirect to the login screen.
- **One active chat per customer, enforced by the database.** Even if the UI somehow allows a double-click, the database refuses to insert a second chat for the same customer. Customers can't accidentally fork their own conversations.
- **Chats ring one agent at a time, not everyone.** When a customer requests a live chat, the system rings the best-fit available agent for 60 seconds, then escalates to the next, then puts the chat in a shared Waiting list. Avoids ringing every agent for every chat (which would create chaos in a 20-agent room).
- **All emails are non-blocking.** If the email server is slow or down, the user's action still completes immediately. Email failures are logged for ops to investigate but never break a request.
- **The whole engineering log is here.** Anything added to the app should be added to this file. The flow is: ⏳ before starting work, ✅ when it's done and verified.
